## INF-146
Patch update ready for review:
- Synced Web FE auth runtime with INF-145 codes: `AUTH_ACCESS_TOKEN_EXPIRED`, `AUTH_REFRESH_TOKEN_INVALID`, `AUTH_REFRESH_TOKEN_REVOKED`, `AUTH_SESSION_INACTIVE`.
- Auth calls now use `X-Client-Type: web` with credentialed Axios requests.
- Forced reauth now persists truthful sign-in notices for inactivity and invalid refresh sessions.
- Forced reauth preserves same-origin redirect targets and ignores cross-origin redirect targets.
- Stored redirect targets prefer current-tab session redirects over stale shared redirects.
- Stored redirect targets after login are checked with the fresh login user instead of stale auth-store state, and skipped if the fresh RBAC helper is unavailable.
- Added minimal cross-tab auth-clear sync via storage event and `BroadcastChannel("auth-session")`.
- Preserved token-only session hints so backend bootstrap can verify cookie/token state before cleanup.
- Direct non-refreshable protected responses now force reauth with the same truthful notice path.
- Semantic missing-session responses now classify as non-refreshable instead of transient verification failure.
- `BroadcastChannel` constructor failure no longer breaks storage-event auth sync.
- Storage cleanup failures are now surfaced in auth store, forced reauth, and manual logout paths instead of being treated as successful logout.
- Protected auth requests remain cookie-based: caller/resolver `Authorization` bearer headers are stripped while `withCredentials` and `X-Client-Type: web` are retained.
- Manual logout cleanup failure now clears the runtime auth state, redirects to sign-in, and persists a warning notice instead of leaving the current tab on a protected page.
- Replayed protected non-refreshable denials now route through canonical forced reauth notice handling.
- Forced reauth redirect continues even when redirect notice persistence fails.
